Sim, exclusivamente. SQL Patch só faz uma coisa: injetar hints na query no momento do parse.
Não força planos, não muda estatísticas, não reescreve a query. Só hints.
O que dá pra fazer com hints (e portanto com patch):

Forçar paralelismo: PARALLEL(8)
Forçar ou impedir um índice: INDEX(t idx_name) / NO_INDEX(t idx_name)
Forçar método de join: USE_NL, USE_HASH, USE_MERGE
Forçar ordem de join: LEADING(t1 t2)
Mudar comportamento do otimizador: OPT_PARAM('parameter_name' 'value')
Desabilitar transformações: NO_QUERY_TRANSFORMATION, NO_UNNEST
Forçar dynamic sampling: DYNAMIC_SAMPLING(t 11)
Forçar materialização de subqueries: MATERIALIZE
E qualquer outro hint válido do Oracle.

O que NÃO dá:

Forçar um plan_hash_value específico (isso é baseline).
Ajustar cardinalidades estimadas (isso é profile).
Mudar o texto da query (isso é Query Rewrite ou view).
Mudar estatísticas de tabela/índice.

Caso interessante: com OPT_PARAM em patch, você pode mudar parâmetros do otimizador só para aquela query. Tipo OPT_PARAM('optimizer_index_cost_adj' 10) para favorecer índice sem mexer no parâmetro global.
Resumindo: patch é "como se eu pudesse colocar hints no código sem mexer no código". Útil quando o código é da aplicação e você não tem acesso.


Para ver todos os SQL Patches do banco:
sqlSELECT name, category, status, force_matching, sql_text, created
FROM   dba_sql_patches
ORDER  BY created DESC;
Colunas relevantes:

name — nome do patch
category — DEFAULT (global) ou outra (precisa setar sqlpatch_category na sessão para casar)
status — ENABLED ou DISABLED
force_matching — YES significa que casa por signature ignorando literais; NO casa só por texto exato
sql_text — texto da query alvo (preview, geralmente truncado)
created — quando foi criado

Para ver os hints armazenados em um patch específico:
sqlSELECT comp_data
FROM   sys.sqlobj$data
WHERE  signature = (SELECT signature FROM dba_sql_patches WHERE name = 'patch_997_parallel');
Esse comp_data é um XML com os hints embutidos — útil para auditoria detalhada.
Para ver se algum patch está ativo num cursor específico (em runtime):
sqlSELECT inst_id, sql_id, plan_hash_value, sql_patch
FROM   gv$sql
WHERE  sql_patch IS NOT NULL;
